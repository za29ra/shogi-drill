# 詰将棋ドリル

小学生（とくに本将棋を覚えたての子）が、**将棋の基本を楽しく学ぶ**ための詰将棋ドリル
Web アプリです。詰将棋をたくさん解くことで、**詰めろの手順・持ち駒の活用・駒の動かし方**が
自然に身につくことを狙っています。

- すべて自動生成。問題は毎回ランダムに作られます（同じ問題ばかりになりません）。
- iPad などのタブレットのタッチ操作に対応。
- 成績は端末内（ブラウザの localStorage）にだけ保存され、外部には送信しません。

## 主な機能（仕様対応）

| 仕様 | 対応 |
| --- | --- |
| 手数・1日の問題数を設定できる | 「せってい」で **1手・3手・5手** の出題と **1日の問題数** を変更 |
| 過去1ヶ月以上の実績表示 | 「きろく」に **過去6週間のカレンダー（ヒートマップ）**＋連続日数・累計・手数別集計 |
| 駒の移動ガイド | 駒（または持ち駒）をタップすると **動かせる場所が光ります** |
| 問題はランダムで自動生成 | 端末内のソルバーで生成・検証。別解（余詰）が出ないよう一意性を確認 |
| 別解を可能な限り出さない | すべての攻め手番で「詰みに繋がる手が1通り」かを検証して採用 |
| 持ち駒あり／なし両方 | 攻め方の持ち駒の有無をランダムに振り分けて両方を出題 |
| タブレットのタッチ操作 | タップで駒を選び→行き先をタップして着手。大きなボタン・ダブルタップ拡大の抑止 |
| 成績のバックアップ（iCloud） | 「せってい」から成績をファイルに書き出し／復元。iCloud Drive 経由で別端末へ移動可能 |

## 遊び方

1. 盤の下側（☗）があなたです。**玉（相手の王）を詰ませば正解**です。
2. 自分の駒や持ち駒をタップすると、動かせる場所が光ります（ガイド）。
3. 行き先をタップして着手します。成れる場合は「成る／そのまま」を選びます。
4. 正解の手を指すと、相手（受け方）が自動で最善の受けを指します。続けて詰ませましょう。
5. 困ったら「ヒント」、答えを見たいときは「答え」を押します。

## 成績のバックアップ（iCloud Drive）

成績は端末内（localStorage）に保存されるため、機種変更やデータ消去で消える可能性があります。
「せってい」画面の **バックアップ** から、安全に保存・移動できます。

- **書き出す**: 「📤 バックアップを書き出す」をタップ → iOS の共有メニューで **「ファイルに保存」→
  iCloud Drive** を選んで保存します（共有非対応のブラウザではファイルがダウンロードされます）。
- **復元する**: 「📥 バックアップから復元」をタップ → 「ファイル」アプリで iCloud Drive 上の
  バックアップファイルを選びます。**現在の記録とは統合**され（同じ日は多い方を採用するので
  二重計上されません）、別端末への引っ越しにも使えます。

> Web アプリはブラウザから iCloud へ直接アクセスできないため、自動同期ではなく上記の手動方式です。
> iOS の「ファイル」アプリが iCloud Drive と統合されているため、保存先／読み込み元として
> iCloud Drive をそのまま利用できます。

## 技術概要

- **フレームワークなしの TypeScript + Vite**。サーバ不要のクライアント完結型。
- 将棋エンジン（駒の利き・王手/詰み判定・二歩・打ち歩詰め・行きどころのない駒・成り）と
  **詰将棋ソルバー**（最短詰め／最長受け／余詰なし判定）を `src/engine/` に実装し、Vitest でテスト。
- 問題生成は **Web Worker**（`src/worker/genWorker.ts`）で裏側で行い、UI を止めません。
- 起動直後やオフラインでも問題が途切れないよう、生成器で作った検証済みの
  **種データ**（`src/data/seedProblems.ts`）を同梱しています。

### 開発

```bash
npm install
npm run dev        # 開発サーバ（http://localhost:5173/shogi-drill/）
npm test           # エンジン・ソルバー・生成器のテスト
npm run build      # 本番ビルド（dist/）
npm run preview    # ビルド結果の確認
npm run gen:seed   # 種データ（src/data/seedProblems.ts）を再生成
```

## GitHub Pages で公開する

このリポジトリには Pages 用のデプロイワークフロー（`.github/workflows/deploy.yml`）が
含まれています。次の手順で公開できます。

1. GitHub のリポジトリで **Settings → Pages → Build and deployment → Source** を
   **「GitHub Actions」** に設定します。
2. デプロイ対象ブランチ（`main` など、ワークフローの `on.push.branches` に含まれるブランチ）へ
   push すると、自動でビルド・公開されます。手動実行（Actions タブの "Run workflow"）も可能です。
3. 公開 URL（例: `https://<ユーザー名>.github.io/shogi-drill/`）を iPad の Safari で開きます。
   「ホーム画面に追加」しておくと、アプリのように全画面で使えます。

> リポジトリ名を `shogi-drill` 以外にする場合は、`vite.config.ts` の `base`
> （または環境変数 `VITE_BASE`）を実際のパスに合わせて変更してください。
